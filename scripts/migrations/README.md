# 数据库迁移纪律（docs/全站优化方案.md W2）

schema.sql 只是**全量图纸**（不可直接执行，仅作最新结构参考）；所有库变更一律走本目录的编号迁移文件。

## 规则

1. **命名**：`NNN-YYYYMMDD-说明.sql`，序号单调递增，永不重跑历史（幂等 DDL 除外，可安全重跑）；
2. **文件头模板**：写明目的（关联方案文档）、远端/本地执行命令、执行记录；执行后回填「执行记录」；
3. **双执行**：生产 `--remote` + 本地各 Worker 目录 `--local` 都要跑（本地各 Worker 共用一份本地库文件）；
4. **合入 main 的迁移必须已在生产执行过**（迁移不随部署自动跑，push main 即部署、靠人工纪律保证先行）；
5. **只增不改**：新表新列可直接做；重命名/删除列/改字段含义一律走「加新列 → 数据迁移 → 停用旧列」三步；
6. **同步图纸**：迁移合入时同步更新 schema.sql，保持图纸 = 线上最新结构；
7. **上线联动**：含库变更的上线，在 docs/上线记录.md（待建）标注迁移编号。
