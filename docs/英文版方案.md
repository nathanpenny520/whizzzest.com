# 英文版方案（i18n / en）

> 2026-09-08 起草。目标：为 whizzzest.com 增加英文版本，中文站保持现状不受影响。
> 本文只做方案与排期，不动代码。
>
> **v1.1 审核修订（2026-09-08）**：① 访客统计须为 `run_worker_first` 补 `/en/*`，否则 EN 流量不入库；② 明确 EN 404 挂载方式（Worker 侧）；③ 未翻译页由「中文兜底构建」改为「不产出该语言版本」；④ AI 招呼语/快捷问题英文化提前至 Phase 1；⑤ PWA 补 per-locale manifest 与 offline 细节；⑥ 补 canonical / og:image / 术语表条目；⑦ 构建校验升级为默认失败项。

## 1. 关键决策

### 1.1 URL 结构：子目录 `/en/`（推荐）

- 中文保持在根路径 `/`，英文放 `/en/...`（如 `/en/heritage/fireworks/`）。
- 理由：同域名继承 SEO 权重；构建产物 `dist/en/...` 由现有 Workers ASSETS 直接托管，零额外设施；hreflang 成对映射简单；将来加 `/ja/` 等同一模式扩展。
- 否决项：子域 `en.whizzzest.com`（SEO 信号分裂、域名/备案配置复杂）；独立域名（花钱、品牌分裂）。
- 根路径保持中文，不做 301 迁移；`x-default` 指向 `/`。
- **不做 Accept-Language 自动跳转**（对 SEO 与爬虫不友好），用语言切换器替代。

### 1.2 内容架构：单模板 + 按语言的数据树（推荐）

- 模板（pages/partials）保持**一份**，所有可见文案进数据层。build.js 增加 `LOCALES = ['zh', 'en']` 循环：zh 产物输出到根路径，en 产物输出到 `dist/en/<同 slug>/`。
- 数据分层：
  - `src/data/en/site.json` —— 站点名/导航/页脚等全局。
  - `src/data/en/<path>.json` —— 与中文一一对应的页面数据。
  - `src/data/strings.json` + `src/data/en/strings.json` —— **UI 文案字典**（aria-label、按钮、页脚标题、灯箱、模拟器标签等目前硬编码在模板/JS 里的串）。模板里用 `{{t.xxx}}` 引用（现有点路径取值引擎天然支持）。
  - `src/data/glossary.md` —— 专有名词对照表（见 §3.3）。
- **Locale 注册表**：build.js 顶部维护唯一的 `LOCALES` 清单（`zh` 为默认语言、占根路径；`en`、`ja`… 各带 `urlPrefix` / `htmlLang` / `hreflang` / `og:locale` / manifest 字段 / 回退链）。路由前缀、hreflang、sitemap、语言切换器、per-locale manifest、翻译覆盖率报告全部由该清单驱动；**除数据文件与注册表外，任何地方不允许硬编码 locale 判断**（详见 §1.5）。
- **回退机制（面向渐进上线与多语言扩展设计）**：
  - UI 文案（strings）：按 `当前 locale → zh` 回退链 deep-merge，任何语言 UI 永远完整。
  - 正文（页面数据）：缺某语言数据文件时**该页直接不产出该语言版本**（不做「EN URL + 中文内容」的兜底构建——那会留下可爬行、hreflang 又不认的孤儿页），且该中文页的语言切换器不渲染对应语言链接（构建期即知有无数据，零运行时成本）；缺页计入覆盖率报告。
  - sitemap 与 hreflang 只收录实际产出的页面：不产出即不收录，hreflang 成对互指天然成立。
  - 效果：某页没翻完不影响整站构建，可分页推进、按页解锁，新语言可以灰度上线；搜索引擎永远不会在 `/en/` 路径下抓到中文正文。
- 否决项：独立英文页目录 `src/pages-en/`（起步快，但模板双份必然漂移，改一处漏一处）。

### 1.3 英文 slug：与中文同 slug（推荐）

- `/en/heritage/fireworks/` 而非 `/en/heritage/firecrackers/`。hreflang 1:1 映射、语言切换器零成本、专有名词（kaikounuo、zhipeng）本就是拼音。翻译 slug 列为将来的可选优化，不进首期。

### 1.4 动态内容（D1）策略：EN 站首期不挂动态板块

- D1 内容（videos / books / attractions / merchants 的标题、简介）均为中文；首期 EN 导航**不放** TV/文库/音乐/景点/商户入口，避免「英文壳 + 中文内容」的半吊子体验。
- AI 助手「花傩」悬浮入口是 footer 全站注入，不随导航减法消失：EN 页保留入口，其招呼语/快捷问题英文化提前至 Phase 1（成本极低，见 §2）；系统提示词与 RAG 双语仍按 Phase 4 二期处理。
- 二期再做：Worker 增加 `/en/tv/...` 等路由 + `worker/strings.js`（按 locale 取 UI 串）+ D1 增加可选 `title_en` / `intro_en` 字段，缺省回退中文；admin/writer 表单加双语输入框。

### 1.5 多语言扩展预留（架构目标：加第 N 种语言 = 「注册一行 + 补翻译」，不碰代码）

- **一次性成本（已由 en 版建设摊平）**：locale 循环构建、strings 机制、hreflang/sitemap 生成器、切换器、per-locale manifest、覆盖率报告。这些都是 N 语言通用逻辑，写死 en 的部分一律禁止。
- **每新增一种语言的固定清单**：
  1. `LOCALES` 注册一行（`ja`：前缀 `/ja/`、`htmlLang: ja`、`hreflang: ja`、`og:locale: ja_JP`）。
  2. `src/data/ja/` 补 `site.json` + `strings.json` + 各页数据（按术语表翻译）。
  3. QA：覆盖率报告清零、构建校验通过。
  - 预估增量：**3–5 天/语言**（AI 初翻 1 天 + 人工校对 2–3 天 + QA 0.5 天），共享资产（图片/WebP 变体/CSS/模拟器/Worker/AI 助手模型层/访客统计）零改动。
- **随 N 自动扩展的部件**：hreflang 互指全量 locale + `x-default` → zh；`og:locale:alternate` 列出全部语言；sitemap 自动扩展；切换器在 ≥3 语言时自动从「双向切换按钮」变为下拉列表面板（模板一次写好，由 locale 清单渲染）。
- **不做自动翻译管线**：上线质量要求人工校对；AI 只做初翻草稿。覆盖率报告使欠账可见，避免「半翻译语言」长期挂在导航上。

### 3.4 合规与保留项

- ICP 备案号在 EN 页脚**必须保留**（不翻译号码，标签可双语）。

### 3.5 明确不做（首期）

- admin / merchant / writer 三个后台工具的国际化（运营者均为中文用户）。
- Accept-Language 自动重定向。
- 英文 slug 翻译、第三语言扩展（架构预留，暂不实施）。
