## 二、W1 访客数据治理 🔴

**执行 [docs/访客治理方案.md](访客治理方案.md)，本节只做摘要与状态跟踪，不重复其内容。**

1. **第 0 步（当天，零改动）**：取消自动刷新勾选 + D1 面板设 Budget Alert。✅ **额度口径已确认（2026-09-08）：5M 为每计费月**；✅ **已决策：不升级 Paid**——安全网全部落在代码侧与使用习惯上；

## 三、W2 数据库迁移纪律 🟠

### 现状

- [schema.sql](../schema.sql) 已 17 张表，CREATE TABLE 与 ALTER TABLE（schema.sql:89-94）及「既有库手工迁移」注释混装，**不可重跑**；
- scripts/ 已自发出现迁移文件（`ai-migrate.sql`、`webauthn-migrate.sql`），文件头已带执行命令注释——纪律有雏形，缺正式化。ai-migrate.sql 头注释已点明正确关系：「schema.sql 是全量权威结构，已有库用迁移文件增量」；
- 未提交的 `webauthn-migrate.sql`（webauthn_credentials 建表）是第一个收编对象。**收编提交时精确 add，防并行会话误伤**。

### 规则（自本方案合入起生效）

1. **目录与命名**：迁移文件统一放 `scripts/migrations/`，命名 `NNN-YYYYMMDD-说明.sql`（如 `001-20260908-webauthn-credentials.sql`）；现有两个迁移文件平移收编为 001 / 002；
2. **文件头模板**（沿用现有风格）：
   ```sql
   -- 迁移 NNN：一句话目的（关联方案文档）
   -- 执行：wrangler d1 execute whizzzest --remote --file scripts/migrations/NNN-xxx.sql
   --       wrangler d1 execute whizzzest --local  --file scripts/migrations/NNN-xxx.sql
   -- 执行记录：生产 YYYY-MM-DD / 本地 YYYY-MM-DD
   ```
3. **执行方式**：远端与本地**双执行**（本地各 Worker 目录的 --local 库同步），执行后回填文件头「执行记录」；**合入 main 的迁移文件必须已在生产执行过**（push main 即部署，迁移不随部署自动跑，靠人工纪律保证）；
4. **schema.sql 退化为全量图纸**：文件头声明「不可直接执行，仅作最新状态参考」；每次迁移合入时同步把变更并入 schema.sql，保持图纸 = 线上最新态；
5. **只增不改**：新表新列可直接做；重命名列 / 删除列 / 改字段含义一律走「加新列 → 数据迁移 → 停用旧列」三步，禁止直接做；
6. **上线联动**：含库变更的上线，在 docs/上线记录.md（W10 交付物）标注迁移编号。

### 验收

下一次真实改库全程按流程走通；schema.sql 与线上结构一致；两个存量迁移完成收编。

## 七、W6 版本统一 🟡

1. **Node 统一 22**：README 修正（CI 实际版本）；构建脚本只用内置模块，无兼容负担；
2. **wrangler 消除漂移**：CI 固定 4.129.0（deploy.yml 四处），本地 `npx wrangler` 会取最新版——「我这好好的，上线就坏」类问题的根源。做法：把 `wrangler@4.129.0`（**精确版本，不带 ^**）加入 devDependencies，本地自动同版；升级流程 = 选无发布的日子、空变更先部署验证；

## 八、W7 密钥清单与部署权限收敛 🟡

**现状**：密钥说明散在各 wrangler.jsonc 注释里（writer:5-6 / admin:4 / merchant:5），无汇总。

### 交付物：docs/密钥清单.md

| 密钥 | 用途 | 存放位置 |
| --- | --- | --- |
| ADMIN_PASSWORD / ADMIN_SESSION_SECRET | 后台主账号与会话签名 | Cloudflare 后台 secret（admin Worker）；本地 .dev.vars |
| MERCHANT_SESSION_SECRET | 商户门户会话签名 | 同上（merchant Worker） |
| WRITER_SESSION_SECRET | 作者门户会话签名 | 同上（writer Worker） |
| SMTP_USER / SMTP_PASS | 门户验证码与表单通知邮件 | Cloudflare 后台 secret；本地 .dev.vars |
| CLOUDFLARE_API_TOKEN | GitHub Actions 部署 | GitHub 仓库机密 |

**只记名称与用途，永不记值**；值只在 Cloudflare 后台 / GitHub 机密 / 本地 .dev.vars。

### 三条制度

1. **部署 Token 最小权限**：CLOUDFLARE_API_TOKEN 仅授权 4 个 Worker 的部署权限（现有 Token 权限需在 Cloudflare 后台复核一次），不用账号级全域 Token；
2. **会话密钥轮换预案**：改 `*_SESSION_SECRET` = 对应门户全体下线（特性也是风险），轮换选低峰期并提前公告；
3. **密钥不进文档 / 截图 / 聊天记录**。

## 九、W8 运维手册 + D1 备份 🟡

### 交付物：docs/运维手册.md

1. **部署**：push main → CI 构建并顺序部署 4 Worker（.github/workflows/deploy.yml）；支持 workflow_dispatch 手动触发；
2. **回滚**：代码坏了 → 回退提交重新部署；部署后才发现 → 平台侧 wrangler versions rollback / 面板回退；两者适用场景写明；
3. **日志**：4 个 Worker 的 observability 入口（含 W4 补开的主站）；
4. **配额观测**：D1 面板 rows read/written + Budget Alert（W1 第 0 步已设）、R2 / AI 用量页位置；
5. **D1 备份**：`wrangler d1 export whizzzest --remote --output=d1-backup-YYYYMMDD.sql`；频率 = 每月一次 + 每次改库前；⚠️ 导出文件含访客 IP/UA 等个人信息，**不进 git、不走聊天工具**，只存本地受控位置；
6. **排障固定顺序（八步）**：分类（四个 Worker 先锁嫌疑人）→ 全挂还是部分挂（全挂查流水线/平台状态，部分挂查对应模块 diff）→ 本地复现 → 看日志 → 查数据（审核状态 / 上下线状态最常见）→ 两层缓存（**PWA 离线缓存**会让部分访客停留旧版，先查 SW 版本戳是否变化）→ 恢复优先于修复 → 留档闭环（文字记录 + 按需附图，不堆二进制截图）。

## 十、W9 后台巨石拆分（择期立项）🟢

### 即刻生效的规矩（无需等拆分）

新功能一律**新开注释分区**，沿用现有 `/* ---------------- xxx ---------------- */` 风格；禁止塞进无关分区。保持分区完整就是为拆分留条件。

### 拆分规程（立项时执行）

- 纯搬家不改逻辑；一次拆一个区；每拆完一区本地过该板块功能 + 构建部署冒烟；
- 目标结构 = API 侧 `admin/api/<域>.js`、页面侧 `admin/ui/<域>.js`（以现有构建方式可行为准）；
- 完成判据 = 单文件 < 1500 行。

### 触发条件

下一个大型功能立项前，或 admin 因体量出现第一次事故时——二者先到为准。
