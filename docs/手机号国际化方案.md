# 门户账号手机号国际化方案 —— 全量国家 + E.164 统一存储

> 文档版本：**v1.0** ｜ 2026-09-09 ｜ 状态：**已实施（本地验证通过；生产迁移 005 与两 Worker 新版部署须同窗口执行，见 §10）**
> 需求：手机号校验过松（`/^1\d{10}$/` 连 10x/11x/12x 等不存在的号段都放行），且仅支持中国 11 位；放开多国手机号注册/登录。
> 已拍板（2026-09-09）：① 国家范围 **全量**（libphonenumber 元数据自带，常用置顶）；② **商户门户与作者门户一致放开**（共享组件少一套逻辑，烟花外贸商户确有海外号场景）；③ 注册成功页/看板 **引导绑邮箱**；④ **短信永不做**——手机号不做归属核验，邮箱验证码是唯一核验渠道（邮箱收码已够，短信运维特别麻烦）。
> 关联：docs/商户功能方案.md、docs/文库方案.md（两门户落地后各自补变更行）；docs/游戏方案.md 阶段三游戏账号直接继承本方案（游戏方案.md 原文"手机号+密码（注册/登录/短信）"中的"短信"与现状不符，随本方案修正）。

## 1. 定位声明（整个方案的地基）

不接短信的前提下，手机号的"核验"只能做到**编号计划级**（号段/长度真实存在），永远做不到**归属核验**。两个概念严格分开，所有 UI 文案如实：

| 概念 | 定位 | 手段 |
| --- | --- | --- |
| **手机号** | 登录账号（类似用户名） | libphonenumber 严格格式核验 + 全局唯一；**不发送短信、不验证归属**，防重号不防伪 |
| **邮箱** | 唯一可验证联系方式 | SMTP 验证码（worker/smtp.js 既有基建），兼做找回通道 |
| 短信 | **永不引入** | 拍板 ④ |

## 2. 技术选型

- **服务端权威校验**：`libphonenumber-js`（用 `/mobile` 元数据子集，只含手机号规则，两 Worker 各打包约 +75KB 原始体积 / gzip 约 +25KB，免费层 1MB 限制内余量充足）。
  - 中国自动收紧为真实号段（1[3-9]，替换现 `/^1\d{10}$/`）；
  - 其他国家按各自编号计划校验长度与号段，且只接受**手机号类型**（座机拒收；美/加 NANP 编号计划不区分移动/固话，无法按类型过滤，属库的已知边界，实测放行）；
  - 这是继 `@simplewebauthn/server` 之后第二个 npm 依赖，同样由 wrangler 打包进 writer/merchant Worker，package.json description 同步补注。
- **客户端不做重库**：仅"仅数字过滤 + 位数提示"；区号列表由 Worker 服务端渲染成 `<option>`（约 240 项，gzip 后约 2KB HTML），前端零额外数据、零校验逻辑，权威判断在服务端报错回显。

## 3. 数据模型：E.164 + 迁移 005

- `phone` 列统一 **E.164 格式**（`+8613800138000`），跨国家唯一性天然成立，现有索引原样复用（merchant_users.phone UNIQUE；writer_users 部分唯一索引 `WHERE phone IS NOT NULL` 不变）；
- 存量数据只可能是中国号（旧正则约束），统一补 `+86` 前缀，无可碰撞风险（迁移前即全表唯一）；
- **迁移 `scripts/migrations/005-20260909-phone-e164.sql`**（幂等，可安全重跑；双执行：生产 `--remote` + 本地 `--local`，执行后回填迁移 README 表格）：

```sql
UPDATE merchant_users SET phone = '+86' || phone WHERE phone NOT LIKE '+%';
UPDATE writer_users  SET phone = '+86' || phone WHERE phone IS NOT NULL AND phone NOT LIKE '+%';
```

- schema.sql 图纸同步：phone 列注释改 E.164（迁移纪律第 6 条），上线后在 docs/上线记录.md 标注迁移编号 005。

## 5. UI：区号选择器 + 引导绑邮箱

- **shared/portal-ui.js `loginPanel`**（两门户登录共用，改一处双生效）：手机号输入升级「区号 `<select>`（国旗 emoji + 区号，原生下拉可键盘跳转，optgroup 分常用/全部）+ 号码输入」，默认 🇨🇳 +86；选择写 localStorage（`wxz_phone_country`）下次免选；`maxlength` 放宽到 15、去掉 `inputmode="numeric"` 的 11 位暗示（保留仅数字过滤）。
- **三处表单接入**：
  1. writer /register 手机号 Tab（writer/index.js 内联页）；
  2. writer /login、merchant /login（即 loginPanel，覆盖 ①②的登录侧）；
  3. merchant /apply（merchant/index.js `widePage` 表单）：`mp_phone` 前加 `mp_country` 下拉；**店铺电话/联系人电话是展示字段，不动**。
- **文案如实**：注册页手机号 Tab 副注：「手机号仅作登录账号使用，不发送短信；建议绑定邮箱，便于用验证码登录与找回密码」——一句同时落实"不暗示归属核验"与拍板 ③。
- **引导绑邮箱（拍板 ③）**：两门户"账号安全"面板在 `email` 为空时，登录邮箱行追加引导文案 + 跳绑定入口（merchant M2.1 已有绑定流程，writer 亦已有）；纯手机号账号无此提示也能用，但明示"未绑邮箱无法自助找回"。

## 7. 诚实边界与缓解

1. **海外号归属完全不可验证**：定位即"登录账号"，防重号不防伪；文案不出现"验证手机号"。
2. **滥用面略变宽**：注册已有 IP 限频 + 蜜罐兜底，暂够用；Turnstile 列为备选增强（有现成技能方案），本方案默认不做。
3. **纯手机号账号忘密码无法自助找回**（现状即如此，全站无找回流程）：靠拍板 ③ 的绑邮箱引导缓解，绑邮箱即自带验证码找回通道。

## 8. 游戏账号继承（docs/游戏方案.md 阶段三）

云存档账号（game_users）登录方式优先级不变，第二项直接采用本方案的国际化手机号账密模式（游戏 Worker 同样 import `shared/phone.js`），即：邮箱验证码 → 手机号（E.164 全量国家）+ 密码 → 通行密钥（可选）。

## 9. 实施顺序与验收清单

顺序：依赖安装 → 迁移 005（生产+本地，回填记录，同步图纸）→ shared/phone.js → 三处 UI/接口 → 文案与引导 → 文档联动（动手前先 `git fetch` 对齐远端）。

验收：

| 用例 | 期望 |
| --- | --- |
| CN 注册 `19912345678` / `12345678901` | 前者过（真实号段）/ 后者拒（1[3-9] 外号段，旧正则会放行） |

| 各国座机号（如 CN 0xx 座机、UK 01xx 固话） | 拒收（仅手机类型） |
