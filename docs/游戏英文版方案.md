## 1. 已拍板决策（2026-09-09）

| # | 决策 | 备注 |
|---|---|---|
| ① | 英文名定为 **Whizzzest Arcade** | 用于 EN 列表页品牌/标题、运行页 document.title、主站 EN 导航 label、术语表；否决 Whizzzest Games / Dream of Flames |
| ② | EN「云端畅玩」分区**保留并标注** | 5 家平台照常渲染（文案英译），免责行写明面向中国大陆、需注册登录、可能受地区限制；否决「EN 隐藏」 |
| ③ | 缺英文元数据的游戏卡**显示中文兜底** | 合并规则 = 字段级 en 缺失落回 zh，不藏卡、列表永远完整；配套轻量检查脚本列欠账（只提醒不拦截）；否决「隐藏该卡」 |
| ④ | 产出方式 = **运行时 i18n** | 单模板 + data-i18n 标记 + i18n.js；否决构建期英文副本（引入构建步骤与「忘跑构建→英文页过期」风险） |

**总基调定调（防文档间前后矛盾）**：②③合起来，子站 EN 采取「英文优先、中文温和兜底」路线，与主站英文版方案 §1.2「缺翻译不产出该语言版本」的严格路线**有意不同**——主站是内容长文，半翻译页会被搜索引擎抓到中英混合正文；子站是工具型界面 + 短标签文案，中文兜底体验可接受，且列表完整性优先。

## 2. 范围界定

**做**：子站全站双语（3 个 HTML + 平台 JS + 2 款自研游戏 + 双语元数据）+ 主站 EN 补 3 处入口 + 子站 hreflang。

**明确不做**：

1. **收录的第三方游戏包内部界面不翻译**——pvz / MC 是中文界面、EmberQuest 是英文界面，保持原样。这是决策⑨（EmberQuest「英文界面保留 + deviceNote 标注」）的对偶执行；改第三方代码撞决策⑥「产物入站、源码不动」铁律。游戏可玩性不依赖读文字，EN 版对应条目的 deviceNote 标注界面语言即可；
2. 后台工具 / AI 助手 / 访客统计——子站不存在这三样，天然不涉及；
3. 主站 build.js 构建架构零改动——子站是独立 Worker（自有 wrangler.jsonc 与域名），与主站构建互不相干；
4. 存档层 / 虚拟手柄 / iframe 三档制等平台机制零改动（语言无关层，见 §3.4）。

## 3. 技术方案

### 3.1 URL 结构

- `game.whizzzest.com/en/` 子目录，与主站 `/en/` 同模式；中文保持根路径。
- 游戏 id 不翻译（`/en/play/minecraft-1.8/`）：hreflang 1:1 映射零成本，id 同时是存档键组成部分（§3.4），翻译即事故。
- 语言切换器：列表页头部一枚双向链接（zh↔en，规则 = 路径前缀增删；语言名用各自语言书写——EN 页显示「中文」、zh 页显示「English」）。运行页顶栏空间不给切换器（从列表页进入语言即随路径）；404 页语言随 miss 路径。

### 3.2 三层文案分离（核心架构）

把子站文案从三个「藏身处」集中到统一的取串机制上，页面与代码只管按 locale 取字：

| 层 | 机制 |
|---|---|
| 静态页（index / play app / 404） | 中文文案处加 `data-i18n` 标记；新增 `game/public/assets/js/i18n.js`：按 `location.pathname` 前缀判 locale → 载入对应字典 → 替换标记处文字、`<html lang>`、title/meta，en 缺条目回退 zh。运行页由 game-shell 在 boot 时完成同样替换 |
| 平台 JS（game-shell / game-save / 自研×2） | 用户可见串改为取串函数调用，字典与静态页共用一份（en→zh 回退链）；game-save 的错误消息同样入字典（Error message 经 toast 透出） |
| 游戏元数据 | games.json 中文母本不动；新增 `game/public/games.en.json` 覆盖表，列表页与运行页渲染时做 zh+en **字段级合并**，缺项落回 zh（决策③） |

**覆盖表字段边界（关键设计）**：只覆盖「给人看」的字段——title / tagline / genre / duration / controls / deviceNote / badge；机制字段 mode / entry / saveMode / saveKeys / keyboardOnly / gamepad / gamepadLayout / gamepadKeymap / orientation / version / tier 永远取母本，双语数据分叉不可能引发行为差异。结构示意：

```jsonc
{
  "games": {
    "huapao-2048": { "title": "…", "tagline": "…", "genre": "…", "duration": "…", "controls": "…", "badge": "…" }
  },
  "platforms": {
    "cloud-netease": { "title": "…", "tagline": "…", "note": "…" }
  }
}
```

- platforms 在 EN 表保留全部 5 家（决策②）；
- EN 的 deviceNote 写**完整英文文案**（不是对中文的追加），界面语言标注（如「界面为中文」）直接写进对应条目；
- 列表页按 locale fetch `games.json` + `games.en.json`（en 文件缺失/404 时只用母本，不崩）；game-shell 在运行页同样合并（顶栏标题与 document.title 用覆盖后的 title）。

### 3.3 Worker 接线（3 件事）

1. `game/worker/index.js` 路由补 3 条（不产出任何 EN 静态文件，一律重写到现有单份页面）：
   - `/en`、`/en/` → 重写 `/index.html`（页面 JS 按路径前缀渲染英文）；
   - `/en/play/<id>/` → 复用现有 `PLAY_RE`（已放宽支持点号 id）重写 `/play/app.html`；
   - 其余 `/en/*` miss → 重写 `/404.html` 并携带语言标记（如查询参数），404 页 JS 据此显示英文 404；
2. `game/wrangler.jsonc` 的 `run_worker_first` 补 `"/en"`、`"/en/*"`——**主站踩过的同款坑**（英文版方案 §3.4）：枚举清单不补，`/en/*` 直达资产层、miss 落中文 404，切链与未来任何 /en 逻辑全部失效；
3. 非 `/en` 路径行为零改动（miss 由 `not_found_handling` 返回中文 404；Worker 异常时 EN 页回落中文 404，可接受——对齐主站 EN 404 的容错思路）。

### 3.4 存档与手柄：零影响（实现前重点核对项）

- 存档键为 `gameId::槽位号`（game-save.js，游戏方案 §2）：**gameId 不参与翻译**，中文页与英文页玩同一款游戏共享同一份存档——切语言不丢档，白送的特性；
- .wsave 格式（magic/format/校验和）无语言因素；导出文件名含展示名 gameTitle → EN 下导出英文文件名，无害；「存档来自其他游戏」判定按 gameId 走，跨语言导入不误报；
- 虚拟手柄按钮纯图形（中文全在注释），零改动；iframe 三档制 / 键快照 / 手柄转发机制不碰。

### 3.5 主站英文版接线（3 处，纯数据文件）

| 文件 | 改动 |
|---|---|
| `src/data/en/site.json` | nav 补「焰境之梦」项：label "Whizzzest Arcade"，href `https://game.whizzzest.com/en/` |
| `src/data/en/index.json` | 「数字体验」区补 game 卡（key 对齐 zh），文案英译，href 指向 EN 游戏库 |
| `src/data/en/about.json` | 「Rebrand & rebuild」条目描述补一句游戏平台上线 |

主站构建架构零改动；main.js 对外链的当前页归属判断已天然免疫跨域链接（main.js 外链短路注释）。

### 3.6 SEO

- 子站内部 hreflang 成对互指：`/` ↔ `/en/`，`x-default` → zh（与主站同规则）；只有列表页需要（运行页、404 均 noindex）。两页互指固定，head 里手写一对 link 标签即可，无构建也能维护；
- EN 列表页 meta title/description 由 i18n.js 运行时替换——Google 渲染 JS 可正常收录；**诚实注记**：HTML 源码仍是中文。若未来 EN 游戏页 SEO 权重变得重要，升级路径 = 同一份字典喂给一个小构建脚本产出静态 EN HTML，架构不推翻；
- 可选加分项：子站补 `sitemap.xml`（仅 `/` 与 `/en/` 两条）+ robots.txt 指向；
- 主站 sitemap 不含子站（跨域本就不该混入）。

## 5. 验收清单（每条可实测）

1. `/en/` 列表页：11 款卡全量（含中文兜底卡如期显示）、语言切换互指、云区 5 家照常且「面向中国大陆」标注到位；
2. `/en/play/` 抽样 ≥5 款：两款自研游戏内文案为英文（含 canvas 文字与结束面板）；iframe 游戏加载 / 全屏 / 横竖屏 / 防误滚零回归；
3. **存档共享**：zh 页存档 → `/en/` 同款读档成功（同 gameId）；.wsave 导出导入回归；
4. `/en/` 下不存在路径 → 英文 404；根路径不存在路径 → 中文 404（不回归）；
5. 主站 `/en/`：导航 / 首页卡 / 时间线三处在位，链接直达 `game.whizzzest.com/en/`；
6. 手机 390px：英文串普遍比中文长，hero / 卡片 / 顶栏无横溢（对齐英文版方案 §3.2 抽查）；
7. 去来源化不回归（决策⑦）：EN 文案自写，不搬运第三方游戏仓库 README / 作者署名段落——翻译素材只取功能文案。

## 6. 风险与坑（提前点名）

1. `run_worker_first` 忘补 `/en/*` → EN 请求绕过 Worker → miss 直接中文 404（主站英文版 §3.4 同款坑，G1 检查项）；
2. 运行时 i18n 依赖 JS：no-JS 访客 / 极慢网络看到中文——子站网格本就 JS 渲染，风险不新增；升级路径见 §3.6；
3. 英文元数据欠账无声堆积：决策③选了兜底显示，坏档不报错——建议 G5 加一个 ~20 行检查脚本（列出缺 en 覆盖的游戏/字段，本地跑，只报告不拦截），并把「同步登记 en 元数据」写进[游戏整合方案.md](./游戏整合方案.md) §5 收录验收清单（后续批次执行）；
4. 英文串长度爆版：顶栏五元素（返回/标题/手柄/存档/全屏）英文化后宽度压力最大，必要时用缩写（Saves / Pad / Full）；
5. 多端协作：动手前先 `git fetch` 确认与远端同步（仓库远端常领先）。

### 8.2 实施中的两处方案简化（均优于原案）

1. **EN 404 不需要语言标记参数**：原 §3.3 设想 worker 重写 `/404.html?l=en`。实际实现更简——`/en/*` miss 直接交还资产层，`not_found_handling` 返回 404 页（**404 状态码原生保留**，不用 worker 手工改写响应），页面 i18n.js 读的是浏览器地址栏路径（`/en/...` 前缀天然在），零参数、零响应体改写。
2. **EN 元数据「隐藏卡」逻辑无需存在**：决策③定的中文兜底 + 字段级合并，让渲染层天然不需要任何隐藏分支；配合覆盖表「机制字段禁止入表」的脚本校验，数据分叉风险归零。

### 8.3 顺手修复的预存在缺陷：module 游戏自动档「只写不读」

- **现象**：验收用例「zh 页存档 → EN 页读同档」失败——自研游戏（花炮合合/接烟花）进度在任何页面间都不恢复，**刷新即丢档**；
- **根因**：壳对槽位 1 自动档只有写入路径（autosave 去抖/切后台兜底），没有回放路径——iframe B 档在 `createIframeGame.mount` 内有回写逻辑，module 游戏的 mount 却每次以新局覆盖自动档。阶段一浏览器端到端验收当时标注「待人工验收」（游戏方案.md §9），真实链路漏检；收录游戏（B 档 keys）不受影响；
- **修复**：boot 在 mount 后回放槽位 1（`shell.saveMode === 'adapter'` 时）——`saves.load(AUTO_SLOT)` → `deserialize` → 立即 `autosave` 压掉 mount 的新局去抖写；回放失败按新档开局（对齐方案 §2「禁止硬拒载」）；
- **回归**：修后「刷新不丢档」「zh↔EN 跨语言读同档」两条用例均过（32/32）。与 i18n 无关、但撞上方案 §3.4 承诺的「切语言不丢档」卖点，属必修。

### 8.6 上线后修订：跨站语言连续性（2026-09-09，部署 2f00cd6f）

用户实测发现：英文游戏页点「回主站」落到中文主站。根因是**跨站/跨页导航链接没认语言**（写死中文目标）——主站侧反方向（EN 导航/首页卡 → game.whizzzest.com/en/）首期已做，游戏站侧漏了。修复：i18n.js 新增 `data-i18n-href` 标记（EN 模式改写链接目标，zh 免动），5 处链接挂标：列表页品牌 logo（→ `/en/`）、头部「回主站」与页脚主站链（→ `https://whizzzest.com/en/`）、运行页返回键与 404 返回按钮（→ `/en/`）。真浏览器 11/11 断言通过（含 zh 零回归）。

**与主站「统一」的边界说明**：URL 结构（`/en/` 子目录）与语言连续性（站内互跳、跨子域互跳均落对应语言版）已与主站统一；**内部机制**上主站是构建期产出静态英文 HTML，游戏子站是运行时换文案（决策④零构建取舍）——用户不可感知差异仅在于网页源码语言与 no-JS 兜底。若将来要求源码级统一，升级路径见 §3.6（同一份字典喂小构建脚本产出 `/en/*.html` 静态件，运行时字典保留给 JS 动态串，与主站「静态页 + `window.__I18N` 注入」的双层结构完全同构）。
