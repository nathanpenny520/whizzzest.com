## 1. 平台侧前置改造（一次性，之后游戏接入 = 拷产物 + 登记 games.json）

### 1.1 存储分界规则：mode 决定存储位置

- **module 模式**（自研，现状不变）：ES module 挂 `ctx.stage`，文件在 `game/public/assets/js/games/`，随 Worker 静态资产部署；
- **iframe 模式**（第三方游戏专用）：`game/public/` 只留平台文件，**一切第三方游戏包统一进 R2 桶 `whizzzest-game`**，key 约定 `g/<gameId>/…`，经 Worker `/g/*` 反代访问（对标主站 `/media/*`），入口 URL 统一 `/g/<gameId>/index.html`。Worker 部署包保持精简，内容更新不触发重部署。

### 1.2 games.json schema 扩展（向后兼容：mode 缺省 = module）

```jsonc
{
  "id": "battle-city",
  "title": "坦克大战",
  "mode": "iframe",            // "module"(缺省) | "iframe"
  "entry": "/g/battle-city/index.html",
  "saveMode": "keys",          // "keys"(B档快照) | "bridge"(A档桥接) | "none"(C档不接管)
  "saveKeys": [],              // B 档：需快照的同源 localStorage 键（逐款实测登记）
  "keyboardOnly": true,        // true = 仅键鼠 → 列表页标注「需键盘」，并作为手柄转发依据
  "deviceNote": "",            // 机型建议（iOS 内存风险等），列表页展示
  // …原有 title/tagline/genre/tier/duration/controls/gamepad/orientation/version/badge 不变
}
```

### 1.3 game-shell.js：iframe 分支

`mode==="iframe"` 时在 `ctx.stage` 注入同源 `<iframe>`（`sandbox="allow-scripts allow-same-origin allow-forms allow-modals allow-pointer-lock"`——五 token 齐备（allow-pointer-lock 供 MC 锁定鼠标视角，随 win12 跟进已在位），`allow="fullscreen"`）填满容器，加载 `/g/<id>/`。同源是关键设计：宿主可直接访问 iframe 的 localStorage（B 档存档快照）与 DOM（手柄转发），且 `game.whizzzest.com` 下所有收录游戏均经人工核对上架（SOP §5），同源风险可控。

### 1.4 存档三档制（对第三方游戏，兼容现有统一存档层）

| 档 | 机制 | 适用 |
|---|---|---|
| **A 档 bridge** | 游戏内嵌桥接脚本，postMessage 对接宿主存档层，全功能（三槽位/.wsave/迁移） | 愿意小改源码的构建类游戏 |
| **B 档 keys（推荐默认）** | 零改游戏代码：games.json 登记 `saveKeys`，宿主定期/退出时把键值快照进统一存档槽（自动档槽 1），导入时回写 | 轻游戏（最高分/关卡进度即全部存档） |
| **C 档 none** | 平台不接管，面板标注「该游戏自行存档于本浏览器」；阶段三云存档再议整目录快照 | 单文件巨物（pvz / Eaglercraft，存档为 IndexedDB 世界数据） |

### 1.5 虚拟手柄 iframe 转发层

现有虚拟手柄合成 KeyboardEvent 只派发到宿主页，**跨不进 iframe**。新增转发：宿主捕获手柄输入 → 同源直接向 `iframe.contentDocument` 重派发。**风险注记**：部分游戏校验 `event.isTrusted`（合成事件为 false），转发为「尽力支持」，逐款验收（验收清单 §5）；不可转发者标注「仅实体键盘」。

### 1.6 去外链清洗（断网可玩铁律的收录版）

每款收录前扫描 `src=`/`href=`/`fetch(` 外链：CDN 依赖本地化（Jump 的 three.js 已本地 ✅）、外链脚本/统计/个人站导航删除、外链图片替换或删除。扫描结果登记进收录记录。

### 1.7 Worker /g/* 反代

`game/wrangler.jsonc` 增加 `r2_buckets: [{ binding: "GAMEDATA", bucket_name: "whizzzest-game" }]`、`run_worker_first` 补 `"/g", "/g/*"`；`worker/index.js` 在路由表增加 `/g/*` → `env.GAMEDATA.get()`（Content-Type 取 R2 httpMetadata 或按扩展名映射，实现直接对标主站 `/media/*` 现成代码）。**缓存策略（迭代期以「更新即时可见」优先）**：文本/代码 `no-cache` + ETag 条件请求（命中 304），媒体类日缓存——游戏包文件名不带 hash，不能用长强缓存（曾因 js 24h 强缓存让用户端在修复后继续吃到坏文件一天）。R2 桶需在 nathanpenny@qq.com 账号创建（`npx wrangler r2 bucket create whizzzest-game`）。

### 7.8 街机死神 4399-196556 定分辨率适配垫片（2026-09-10，业主拍板「等比放大铺满」）

**现象**（上线后用户实测反馈）：游戏以原生 800×600 钉在运行舞台**左上角**（实测容器 rect (8,8)），四周全黑。游戏本体运行正常（能进战斗），纯画面适配缺失。

**根因（三层叠加，线上真浏览器探针实测）**：① 该包是定分辨率 Unity WebGL（UnityLoader 时代），entry 写死 `#gameContainer` 800×600——在 4399 原站其播放器 iframe 恰好 800×600 故满格；② `UnityLoader.instantiate()` 会**重写容器内联样式**（实测 `margin:auto` 被归零、补 `position:relative; background:#231F20`），连原页仅有的水平居中也丢；③ 运行壳 `.game-frame` 铺满 `#stage` 后 iframe 内部 1:1 显示，全链路无任何缩放。运行时自愈（runtime-repair）只管 404 不管布局，非当日回归，是定分辨率包的固有形态。

**修法（entry 注入 fit 垫片，收录产物内自洽，不碰运行壳）**：`index_https.html` 尾部注入 `<style>+<script>`——容器 `position:absolute; left/top:50%; transform:translate(-50%,-50%) scale(var(--fit))`，脚本按 `min(innerWidth/宽, innerHeight/高)` 置 `--fit` 并监听 resize（全屏切换自动生效）。关键点：**`!important` 压过 UnityLoader 的内联样式重写**（样式表 important > 内联非 important）；`offsetWidth` 不受 transform 影响，恒读布局尺寸 800×600，无需写死数值。等比 contain：比例不符处留黑边、小屏自动缩小（手机横屏可玩）。代价：放大为插值放大（定分辨率 Unity 固有，画质无损方案是「只居中不放大」，业主选铺满）。

**通用化**：批次二后续若再收定分辨率包（Unity/固定 canvas 类），直接复用该垫片（选择器按包内容替换），**fit 缩放与输入重映射一体上**（下段）——登记为收录管线候选工序，归批次二a 上传器/管线范围。

**追加修（上线当日业主实测反馈点击失灵）**：框架 .unityweb 为 gzip（魔数 `1f8b`），解包实测 `fillMouseEventData` 记 `clientX-rect.left` **裸偏移**——Emscripten 时代鼠标路径无归一化除法，假设画布 CSS 尺寸恒等于背存 800×600（原生 1:1 时恰好成立，故垫片前能点）。transform 缩放后 rect 变 1224×918，点击坐标按 1.53× 飞出按钮（本地复现：StartGame 正中点击菜单无响应，Enter 亦无效——菜单为鼠标命中区驱动）。修法：垫片补**输入重映射**——`window` 捕获阶段截 mousedown/mouseup/mousemove → 按 `背存/rect` 比反算回画布坐标 → `stopImmediatePropagation` 原事件 + 以修正坐标在原 target 重派发 MouseEvent（`isTrusted=false` 早退防重入死循环；未缩放 |rect-背存|<1 不干预）。键盘事件不经此路径零影响。验收：本地+线上 play 页真浏览器点击 StartGame 均正常进关（战斗场景/血条/敌人列队渲染正常截图）。

**验证**：本地静态服务 + 无头浏览器两视口实测——1704×918 → scale 1.53，容器 1224×918 水平居中满高（偏差 0px）；缩窗 900×500 → scale 0.833，666.7×500 精确居中（偏差 0px），resize 路径生效；标题屏渲染截图正常；输入重映射后菜单点击进关双端（本地/线上）通过。复测脚本 `_probe-196556-geometry.mjs`（几何）+ `_probe-196556-click.mjs`（点击，play 页自动穿透 iframe 取子帧坐标）。

### 8.1 定位与边界（为什么只能跳转、不能嵌进来）

- **技术上嵌不了**：云游戏是流媒体平台（游戏在对方机房跑、画面推流过来），普遍拒绝 iframe 嵌套（X-Frame-Options/CSP）+ 登录墙 + 账号风控；与 win12 那种「单页应用恰好可嵌」性质完全不同；
- **性质上不该嵌**：它们是「平台」不是「一款游戏」——本站运行壳的存档三档、虚拟手柄、全屏/横竖屏对它们全部无意义，嵌进来只是画蛇添足；
- **与既有铁律不冲突**：「断网可玩、产物入站」（决策⑥）只约束**收录的游戏**；外链入口不在本站页面加载任何第三方资源，用户是显式点击跳出去的；
- **与决策⑦不冲突**：不涉及收录产物，页面明示「第三方平台，与本站无关」；
- **商业边界**：学生比赛项目无商业化（`rel="nofollow"` 不涉推广返佣）；跳转目标均为官方平台。
