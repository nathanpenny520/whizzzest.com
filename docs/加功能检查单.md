# 加功能检查单（docs/全站优化方案.md W3 交付物）

> 每次新增功能时对照本单打勾。三处手工清单是历史事故高频来源——漏改的后果见各条说明。

## 一、三处手工同步清单（加动态功能必查）

| # | 清单 | 位置 | 什么时候要改 | 漏改后果 |
| --- | --- | --- | --- | --- |
| 1 | **Worker 优先路径** | 根 [wrangler.jsonc](../wrangler.jsonc) `assets.run_worker_first`（约 20 条） | 新增动态页面 / 新 API 前缀时 | 新路径落不到 Worker：API 404，动态页被当静态资产处理 |
| 2 | **资产指纹** | [build.js](../build.js) `versions` 对象（当前 6 项） | 新增全局 CSS / JS 文件时 | 新文件无 `?v=` 指纹，被 `/assets/*` 一年 immutable 缓存钉死旧版，改了用户也看不到 |
| 3 | **sitemap / robots 动态页** | [build.js](../build.js) sitemap 段与 robots.txt 段（手列 5 个动态频道） | 新增 Worker 渲染的内容频道时 | 新频道不被搜索引擎收录 |

注：PWA 预缓存清单与页面 `?v=` 回写是**自动**的（构建从 versions 与页面列表推导），无需手工登记；新增静态页面（pages/ 目录）也自动发现，零登记。

## 二、落位规则（新东西往哪放）

- **静态页**：`pages/` 建目录 + `data/` 同名 JSON——构建自动发现，零登记；
- **动态功能**：`worker/` 下新增领域文件（照 `tv.js` / `music.js` 模式），在清单 1 登记，`worker/index.js` 只做分发、禁止堆业务；
- **门户共用 UI**：只改 [shared/](../shared/)（portal-ui.js / webauthn.js），admin / merchant / writer 三门户同时生效；
- **后台功能**：admin/index.js **新开注释分区**（`/* ---------------- xxx ---------------- */`），禁止塞进无关分区——保持分区完整就是给将来拆分（W9）留条件；
- **数据库变更**：一律走 `scripts/migrations/` 编号迁移（纪律见该目录 README），schema.sql 同步更新图纸。

## 三、变更自检四问（每次合入前过一遍）

1. **构建能过吗？** `node build.js`；
2. **本地关键页能开吗？** 首页 / 文库 / 商户 / 后台登录；
3. **动了数据库吗？** 动了 → scripts/migrations/ 编号迁移 + 生产先行执行（先于代码合入）；
4. **动了清单类配置吗？** 动了 → 对照本单第一节逐条打勾。

## 四、发布（见 docs/运维手册.md）

push main → CI 构建部署 4 Worker → 按 docs/上线记录.md 记一行。
