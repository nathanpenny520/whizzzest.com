## 1. 定位与架构

**产品定位**：浏览器原生单机游戏平台。所有游戏运行逻辑 100% 在用户浏览器本地执行，官方服务器不做任何游戏运算，只负责静态资源分发与（阶段三的）存档备份。断网、后端宕机、清后端，游戏 100% 正常玩。

**平台口号：「短篇可通关」**——每款 20–90 分钟、有结局、一次玩完；「一节课、一班车里能通关的精品」。与 4399 等拼内容量的路线正面错开，是比赛材料的核心叙事，也是 §3 类型准入矩阵的统一判据（凡与「短篇可通关」冲突的长线品类一律降档）。

**与主站同栈，不引入第二套体系**：Workers 静态资产 + D1 + R2（不采用 Cloudflare Pages，Pages 功能正在向 Workers 收敛）。

```
玩家：game.whizzzest.com（新 Worker whizzzest-game，同 writer/merchant 部署模式）
  游戏库列表页（静态）→ /play/<id>/ 统一运行页（游戏壳：画布/iframe + 存档面板 + 全屏 + 触屏手柄）
  游戏逻辑 100% 浏览器本地：H5 原生 ｜ 开源 WASM 模拟器内核
  本地存档：IndexedDB（persist()）+ 手动导出/导入 .wsave 文件
  大资源（模拟器内核 WASM、ROM、大游戏包）：game Worker 挂 R2 绑定直读（对标主站 /media/ 代理）
  ↓（阶段三）
云存档：Workers API（仅 上传/下载/列表）+ R2 存档文件 + D1 存档索引
账号：game_users 独立表（账号隔离惯例，对标 writer_users），三种登录方式照抄门户已验证模式
```

| 决策 | 结论 | 理由 |
|---|---|---|
| 部署形态 | 独立子域名 Worker `whizzzest-game` | 与主站内容气质隔离，保护文旅主站品牌与 SEO；部署/构建互不拖累（同 writer 先例） |
| 游戏目录数据源 | 阶段二用**纯静态 `games.json`**（build.js 构建期烘页面），不上 D1 | 「服务器零参与」更纯粹、零接口零运维；需要后台化管理时再对标万载TV 上 D1 |
| 大资源存储 | R2（game Worker 直挂绑定），静态资产仅放小文件 | Workers 静态资产单文件上限 ~25MB，GBA ROM 最大 32MB、WASM 内核不小，一律走 R2 |
| URL 规划 | `/`（游戏库）→ `/play/<gameId>/`（统一运行页） | 每游戏独立 URL，可分享 |

## 2. 本地存档系统（阶段一核心，全站统一）

> 原始规划两处断言已修正：①「永久存在 IndexedDB」不成立——浏览器在磁盘压力下可驱逐存储，iOS Safari 约 7 天不访问即可能清理；②「所有游戏共用一套存储逻辑」低估成本——各引擎存档位置/格式不同，需每游戏一个适配器。

**统一存档适配层（唯一正确做法）**：
- 平台层提供统一 API（读写/列槽位/导出/导入/版本管理），**每款游戏实现一个 adapter** 桥接其存档数据（模拟器游戏天然标准：直接接管内核的 `.sav`/`.state`，反而是最简单的一类）；
- 存档键：`game/<gameId>/slot<n>`；载荷 = JSON 元数据（`gameId / version / updatedAt / checksum`）+ 游戏原始存档数据；
- 导出文件统一扩展名 **`.wsave`**（JSON 头 + 载荷，单文件、可分享、可备份）。

**持久化保障**：
1. 页面加载即调 `navigator.storage.persist()` 申请持久化存储，并在「关于」里展示授予状态；
2. 运行页常驻「导出存档」按钮；未获持久化授权时显著提示玩家导出；
3. **版本策略：存档带版本号，游戏升级后不兼容时「警告 + 尝试迁移」，禁止硬拒载**（硬禁载等于每次更新集体炸档）。

**三备份机制（强制规范）**：IndexedDB 自动存档（日常）→ `.wsave` 手动导出（清缓存兜底）→ R2 云端（阶段三，跨设备）。

**阶段一强制规则**：任何游戏未完成存档 adapter 不得上架；游戏运行 100% 脱离后端，断网可玩。

## 3. 内容策略（阶段二）

| 来源 | 说明 | 定位 |
|---|---|---|
| 收录开源 H5 | itch.io 等开源/免费授权小游戏，逐个核对授权条款并登记 | 快速填充游戏库数量 |
| 自研高质量原创 | 创新优先，是**比赛评审的主打亮点** | 平台核心价值 |
| 本地题材原创（可选） | 花炮/傩舞/夏布/方言元素的原创小游戏 | 差异化 + 反哺主站文旅引流 |

**自研优先级路线（按「单位开发成本的质量产出」排序，比赛主推）**：
1. **点击式密室解谜**（傩面/花炮作坊主题，Rusty Lake 式）——最能代表平台气质与本地题材；
2. **文字 AVG / 侦探怪谈**——单位成本质量产出最高，纯 vanilla JS 自研契合主站零依赖风格，自研游戏存档天然走统一 adapter；
3. **微型回合策略 / 卡牌 PVE**——系统深度展示，证明"浏览器里能做有脑子的游戏"；
4. **得胜鼓节奏 + 烟花弹幕 STG**——开发快、现场演示炸场；
5. 技术压轴特例：一件 3D 氛围短片 + AI NPC 彩蛋。

**游戏接入 SOP（每款上架必过清单）**：
1. 授权/来源核对并登记（开源许可原文随包保留；ROM 类按已拍板④）；
2. 存档 adapter 适配 + 「刷新不丢档」验收；
3. 移动端验收：触屏可玩、横竖屏正常；
4. 套统一游戏壳（标题/操作说明/全屏/存档面板/触屏手柄）；
5. 登记 `games.json` 上架。

### 游戏类型准入矩阵

适用于**自研与收录**两个来源的立项判断，每款立项前先对表定档；档位统一服从「短篇可通关」定位。判定维度：① 浏览器/触屏适配度 ② 本地运算可行性 ③ 短篇体量下的内容成本 ④ 比赛演示效果。

**✅ 第一梯队：主推（自研主打）**

| 类型 | 理由 |
|---|---|
| 文字 AVG / 视觉小说 / 互动侦探（含多结局分支、海龟汤式口头推理） | 资源小、叙事驱动；触屏原生；自研存档天然走统一 adapter；花炮/傩舞怪谈题材直接落地 |
| 点击式解谜 / 密室逃脱 / 环境谜题 | 场景化美术可控、氛围强；Rusty Lake 式短篇是网页游戏最成型的精品范式；本地题材契合度最高 |
| 假界面解谜（整个游戏是一台「手机/电脑桌面」） | 纯 DOM/CSS 即可实现，体量极小而创新感极强；比赛差异化亮点 |
| 微型回合策略 / 叙事卡牌 PVE（含单机自动战斗） | AI 全部本地运算、单局闭环；系统深度即技术展示；回合制无输入延迟问题 |

**✅ 第二梯队：备选/补充**

| 类型 | 理由 |
|---|---|
| 短篇像素 RPG（分章完结） | 一章一个完整故事；注意 RPG 是「每分钟游戏内容」开发成本最高的品类，严格控规模 |
| 单机塔防（关卡制） | 浏览器经典品类；触屏点按放置友好；「烟花塔防」题材现成 |
| 轻量平台跳跃 / 横版动作（含短篇 metroidvania） | Canvas2D 60fps 足够（无需 WebGPU/Wasm）；真约束是触屏精度——键盘优先、触屏版降低操作难度要求 |
| 轻量音乐节奏 | **得胜鼓（万载非遗）题材全场最贴**；AudioContext 时钟做判定同步；蓝牙耳机延迟给提示 |
| 触屏 STG / 烟花弹幕 | 手指拖动是触屏最精准的输入方式；Canvas2D 完全跑得动；题材天然契合 |
| 有限目标微型模拟经营 | 有通关结局不是无限经营；「办好一场烟花大会」主题现成 |
| 单人轻量 Roguelike | 单局独立、存档只存解锁内容；注意随机词表/平衡性的内容量 |
| 同屏双人 / 热座小游戏合集 | 同一设备 = 仍是单机架构，零服务器；双人同屏现场演示效果好 |
| 桌游 AI 对战（象棋/五子棋/军棋/UNO 类） | 本地 minimax/搜索，AI 强度即技术展示；零美术成本 |
| 物理益智（切割/堆叠/弹射，关卡制） | 2D 物理成熟；触屏拖拽原生；关卡制天然短篇 |
| 短局跑酷（单局 3–5 分钟，分数导向） | 单局短、触屏单击原生；「无限跑」与通关定位不符，故只做分数挑战型 |
| 微型 SRPG 战棋 | 回合制无延迟问题；地图/数值工作量偏大，酌情立项 |

**✅ 第三梯队：低成本填充**

| 类型 | 理由 |
|---|---|
| 数字逻辑谜题（数独/密码/空间拼图/2048/华容道） | 体量极小、开发快；技术展示价值低，只做填充 |
| 经典纸牌 / 扫雷 | 零美术、常青流量 |
| 成语 / 汉字 / 填字类 | 文化向契合主站；零美术 |
| 体育小游戏（点球、时机条类） | 小体量、单机制即可成立 |
| 放置 / 挂机（轻量） | 同填充档处理；不做主力 |
| 创意互动玩具 | 无目标涂鸦/音乐盒/粒子玩具；主站「数字烟花」同款定位的引流件 |
| 非遗科普互动闯关 | 问答/文物拼图/方言学习；文化传播立意是比赛加分项 |
| 模拟器游戏 | homebrew 短篇 + 完整 ROM（按决策④）；「截取原作章节」技术不可行，不做此设想 |

**⚠️ 谨慎 / 特殊**

| 类型 | 理由 |
|---|---|
| AI 增值叙事（LLM NPC 对话） | 主站已有 Workers AI 绑定先例，是**比赛最强技术演示点**；但违反「断网 100% 可玩」铁律 → 必须做成联网增值、离线降级（断网隐藏 AI 选项、主线照常通关），处理方式对标云存档 |
| 无限模拟经营（种田/无限建造） | 真瓶颈不是存档体积（通常 <5MB，persist+导出已兜底），而是内容 treadmill 开发量 + 与「短篇可通关」定位冲突 + 静态平台给不了持续更新节奏 |
| 中小型轻 3D 探索 | 用 Three.js/WebGL（WebGPU 在老设备覆盖差）；瓶颈是美术产能而非加载（R2 分发现成）；特例做**一件**（万载古城夜景漫游 / 360 全景密室）作技术展示，不做平台主力 |
| 硬核高速动作（高速 FPS/格斗/高反应平台） | Web 输入延迟 + 触屏精度无法对标原生客户端；仅小体量 Demo 可尝试 |

**❌ 禁入（架构/环境硬性冲突）**

| 类型 | 理由 |
|---|---|
| 多人 PVP 竞技（MOBA/FPS/IO）/ 跨设备实时联机合作 | 需权威服务器校验与状态同步；架构明令服务器不做游戏逻辑 |
| MMORPG / 大型开放世界 / 大型多人沙盒 | 服务端世界状态 + 海量资源包，与单机底层机制冲突 |
| 云串流 | 本地运算架构，无 GPU 云，成本体系不符 |

**平台级特色玩法（不属于单款游戏，平台自带的加分项）**
- **跨站 ARG**：把解谜线索藏进 whizzzest.com 文旅各页与游戏站各处，localStorage 旗标串联成一条全站解谜线——开发成本极低，比赛叙事极强；
- **Workers AI 彩蛋 NPC**：同 AI 增值叙事的离线降级原则；
- **跨游戏统一成就/收藏**：扩展阶段四的收藏规划为平台级徽章体系。

## 4. 移动端与体验（并入阶段一，不是后期优化）

国内休闲玩家绝大多数在手机上，触屏方案是本平台的命门级工作，与基座同期完成：
- **虚拟手柄**（十字键 + AB 键，模拟器游戏必备）、横竖屏自适应、全屏 API；
- 音频解锁（iOS 需用户手势触发后才能出声）、低端机性能分级（降帧/关滤镜）；
- iOS Safari 注意内存上限（大型 GBA ROM 有崩溃风险，游戏库标注机型建议）。

## 5. 模拟器方案（阶段二子项）

| 项 | 结论 |
|---|---|
| 内核选型 | **EmulatorJS**（一个包覆盖 FC/SFC/GB/GBC/GBA/MD 等）+ **js-dos**（DOS 专用），均为开源 WASM，随包保留其许可证文件 |
| 首期机型范围 | FC / GB / GBC / GBA / MD / DOS——这些**无需主机 BIOS**；PS/SFC 部分场景需用户自供 BIOS，首期排除 |
| ROM 托管 | R2 桶（game Worker 直读），按已拍板④执行 |
| 预留开关 | 运行页同时支持「拖入本地 ROM」入口（内核同一套），未来如需合规化，一键切为仅自带 ROM 模式 |

## 6. 云存档与账号（阶段三，先规划、后实施）

**定位**：云存档只是备份与跨设备工具，登录解锁，不登录完全不影响游玩。

**数据模型草案（届时迁移，现在不建表）**：
```sql
CREATE TABLE game_users (           -- 独立账号体系（对标 writer_users，账号隔离惯例）
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  phone TEXT,                       -- 可空，部分唯一索引（对标文库 v1.1）
  email TEXT,
  password_hash TEXT,
  created_at TEXT DEFAULT (datetime('now'))
);
CREATE TABLE game_saves (
  user_id INTEGER NOT NULL,
  game_id TEXT NOT NULL,
  slot INTEGER NOT NULL DEFAULT 1,
  version INTEGER NOT NULL,
  checksum TEXT,
  size INTEGER,
  r2_key TEXT NOT NULL,             -- saves/<user_id>/<game_id>/slot<n>
  updated_at TEXT DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, game_id, slot)
);
```

**API 草案**：`POST /api/saves/<gameId>/slot<n>`（上传覆盖）、`GET /api/saves/<gameId>`（列表+下载）、全走 game Worker，鉴权用独立 `GAME_SESSION_SECRET` 会话 Cookie。

**登录方式优先级（复用门户已验证基建）**：
1. **邮箱验证码**——主站 Worker 已有 `smtp.js` 发信基建，最先落地；
2. **手机号+密码**——writer/merchant 已跑通同款（注册/登录；手机号仅作登录账号、不验证归属、不发短信，E.164 全量国家，见 docs/手机号国际化方案.md），照抄模式；
3. 通行密钥（可选增强，对标文库 v1.3）。

**额度盘点**（免费层）：Workers 10 万请求/天、R2 10GB 存储、D1 5GB——起步充裕；**R2 是用户过万后第一个瓶颈**，届时存档做单用户配额。
