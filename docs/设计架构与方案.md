### 1.6 旧站弊病诊断与重构对策（打开思路，核心章节）

> 用户要求：之前网站弊病多，这次重构**全部解决、不被旧结构束缚**。下表逐条列弊病 → 对策 → 对应新方案落点。

| # | 旧站弊病（实抓/实测） | 重构对策 | 新方案落点 |
|---|---|---|---|
| 1 | **SPA 客户端渲染**：首屏白屏、搜索引擎抓不到内容 | 改为多页静态 HTML，首屏即完整内容 | §4 原生多页 |
| 2 | **单页长滚动**：所有板块堆在首页，信息密度过高 | 按主题拆 6 个独立页 + 清晰导航层级 | §6 页面规划 |
| 3 | **框架 JS 体积大**：Vue 全家桶分包，移动端加载慢 | 零框架运行时，JS 按功能拆文件、按需加载 | §4 技术选型 |
| 4 | **SEO 基建缺失**：无 sitemap/robots/结构化数据/规范 OG | build.js 自动生成 sitemap.xml（含 hreflang alternates）、robots.txt、每页 canonical + hreflang 互指 + JSON-LD（LocalBusiness/TouristAttraction）+ 每页 1200×630 绝对 URL og:image | §5 结构 / P6 |
| 5 | **图片无响应式**：固定尺寸、无 srcset、无懒加载 | srcset/sizes + loading="lazy" + 首屏关键图 preload | §6 交互模块 |
| 6 | **无版本管理/无 CI**：部署靠手工传 ECS，改坏了难回滚 | Git 全量管理 + Workers 自动部署 + 分支预览 + 一键回滚 | §9 流水线 |
| 7 | **无安全头**：缺 CSP/X-Frame-Options/Referrer-Policy | `_headers` 文件（CSP 宽松起步或 report-only，避免上线即白屏）+ Cloudflare 安全规则 | P5 |
| 8 | **无性能监控**：好坏无量化 | Cloudflare Web Analytics + 性能预算（LCP<2.5s，首屏 JS<30KB） | P6 |
| 9 | **品牌散乱**：.top 域名 + outlook 杂邮箱 | 统一 **whizzzest.com** 主域 + 阿里云企业邮（已配好） | §8 已定 |
| 10 | **无障碍缺失**：无 ARIA/键盘导航/对比度把控 | 语义化标签 + ARIA + 键盘可达 + 对比度 ≥4.5:1 | P3 规范 |
| 11 | **移动端体验粗糙**：无 PWA 基础、无离线能力 | manifest + 手写 service worker（约 50 行，缓存静态壳） | P3 可选 |
| 12 | **主题曲/素材外链脆弱**：音频依赖旧站 JS 拼接 | 素材全部下载到仓库静态托管，页面零外链 | P2 迁移 |

> - **信息架构**不再复制旧站板块顺序，按访客动线重排：游客（玩什么）→ 吃货（吃什么）→ 文化控（看什么）→ 商务（烟花产业）。

## 2. 核心设计原则（为什么选原生）

| 原则 | 说明 |
|---|---|
| **零框架运行时** | 页面就是纯 HTML/CSS/JS，浏览器直接跑，无 Vue/React/Nuxt 任何一层 |
| **零依赖构建** | build.js 只用 Node 内置 fs/path，不装任何 npm 包，无 lockfile、无 node_modules |
| **零 EOL 风险** | 没有框架版本迭代问题（刚经历 Nuxt 3 EOL），文件 10 年后照样能打开 |
| **平台层同思路** | 托管选 **Workers（Static Assets）**——Cloudflare 当前主推、持续演进的产品线（Pages 新特性已冻结），平台层也贯彻"零 EOL" |
| **SEO 天然最优** | 每个页面是完整 HTML，搜索引擎直接收录，无 SPA 空白首屏 |
| **全掌控** | 每行代码自己写的，没有"魔法"，出问题可全链路排查 |
| **部署最简** | dist/ 静态目录直接上 Cloudflare Workers，构建命令就是 `node build.js` |

## 4. 技术选型（原生版）

| 层 | 选型 | 说明 |
|---|---|---|
| HTML | 手写语义化多页静态页 | 每页一个完整 .html，含独立 title/meta/canonical/hreflang |
| CSS | 手写，CSS 变量 + Flex/Grid 响应式 | 单一 style.css；**视觉语言 = Apple 视效风格（v2.3 定稿）**：系统字体栈（SF/PingFang）、毛玻璃吸顶导航、#f5f5f7/#fff 交替分节、大标题大留白、克制动效；焰色 #d64524 仅作点缀（kicker/按钮/高亮） |
| JS | 原生 ES Modules | 按功能拆文件：main.js（导航/滚动）、fireworks.js（数字烟花 Canvas）、player.js（音频）、contact.js（表单，P4） |
| 构建 | **build.js**（Node 内置 fs，零依赖，**预估 150–300 行**） | 拼接公共片段 + 替换 meta 占位符 + 从 src/data/ JSON **构建时渲染**列表内容 + 生成 sitemap.xml（含 hreflang）→ 输出 dist/ |
| 静态托管 | **Cloudflare Workers（Static Assets）** | 构建命令 `node build.js`，输出目录 dist/，assets 指向 dist/ |
| 动态接口 | 单入口 Worker（worker/index.js） | fetch 按路径分发 /api/*，D1/KV 绑定写在 wrangler 配置 |
| 数据库 | D1（可选） | 表单记录；Free 5GB |
| 邮件 | 阿里云企业邮（已有） | 仅作表单通知（尽力而为）；权威数据在 D1 |
| 分析 | Cloudflare Web Analytics | 免费、免 Cookie 弹窗 |
| 版本管理 | GitHub `whizzzest.com`（已连接） | main 分支自动部署（Workers Builds） |

**刻意不用的东西**：Vue、React、Nuxt、Tailwind、任何 npm 运行时依赖。可以用的工具边界：Node（仅跑 build.js）、Cloudflare Workers（原生 JS 单入口）。

## 11. 风险与注意事项

1. **导航/页脚维护**：集中在 partials/ 改一处，build.js 全站生效（这是原生方案的关键设计，务必遵守"公共部分只改 partials"）
2. **双语同步**：en/ 内容改动需手动同步中文版——宣传站内容低频更新，可接受
3. **无 TypeScript**：用 JSDoc 注释（`/** @type {number} */`）+ VS Code 可获类型提示，弥补部分类型安全
4. **免费额度**：Workers 静态资产请求免费；Worker 动态请求 10 万次/天；D1 5GB——宣传站量级完全够
5. **SMTP 发信**：先 spike 后实现（§7 三期制）；Email Routing 路线已删除（MX 冲突）
6. **图片版权**：旧站图片注意来源标注，逐步替换自有拍摄图
7. **主题曲音频**：从旧站 JS 定位音频真实 URL 下载到 public/audio/，勿引用旧站外链；版权归属确认
8. **框架迁移后悔药**：原生结构清晰，未来若内容膨胀到 >10 页，迁移到框架成本很低（页面和内容都是现成的）
9. **二维码**：公众号二维码是实体物料，主域方案下二维码图片本身不变，零影响
10. **CSP 起步**：先宽松或 report-only，验证无报错后再收紧，避免安全头自己把自己拦白屏
11. **平台差异**：Workers 与 Pages 的 `_headers`/`_redirects` 语法一致，但部署/绑定走 wrangler.jsonc——P1 搭骨架时即按 Workers 结构落，不留 Pages 残留
