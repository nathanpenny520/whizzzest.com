# 运维手册（docs/全站优化方案.md W8 交付物）

> 面向「半年后的自己」和接手的新人：怎么部署、怎么回滚、怎么看日志、怎么备份、出了事按什么顺序排查。

## 一、部署

- **常规**：push `main` → GitHub Actions（[.github/workflows/deploy.yml](../.github/workflows/deploy.yml)）构建 + 顺序部署 4 个 Worker（主站 → admin → merchant → writer）；Node 22 + `npm ci` + wrangler 4.129.0（与 devDependencies 固定版本一致）；
- **手动触发**：Actions 页 `workflow_dispatch`；
- **本地紧急部署**（不等 CI）：`cd admin && npx wrangler deploy`（本地需 wrangler login 对应账号）；npx 会取 devDependencies 里的固定版本；
- **数据库变更不随部署走**：必须先用 `wrangler d1 execute whizzzest --remote --file scripts/migrations/NNN-xxx.sql` 执行迁移（纪律见 scripts/migrations/README.md），**先迁移后合入代码**。

## 二、回滚

| 场景 | 做法 |
| --- | --- |
| 代码改坏了，还没定位 | `git revert`（或回退提交）重新 push——回滚即重新部署 |
| 部署后才发现，想先恢复 | Workers 面板 → 对应 Worker → Deployments → 回滚到上一版本（或 `npx wrangler rollback`）；恢复后再慢慢修 |
| 数据库变更出问题 | 迁移只增不改，不做回滚——新代码回退后新表/新列留在库里无害 |

## 三、日志

- 四个 Worker 均已开启 observability（主站 2026-09-08 补开）：Cloudflare 后台 → Workers → 对应 Worker → Logs，可看实时日志与历史（含报错时间 + 请求路径）；
- 主站每日访客清理 cron（北京 04:17）的执行结果看 scheduled 触发的 `console.log`（`visits retention: …`）；
- `scripts/smoke.sh` 的请求 UA 尾缀 `whizzzest-smoke`，可在日志中识别。

## 四、配额观测（免费计划）

| 资源 | 入口 | 关注点 |
| --- | --- | --- |
| D1 | 数据库面板 → Metrics | **Rows read / Rows written**（按计费月 5M / 5M）；已设 Budget Alert；超额后查询直接报错（主站动态页 + 后台全挂，纯静态不受影响） |
| Workers | Workers 面板 | 每日请求数 |
| R2 | R2 面板 | 每月操作数（读取流量免费） |
| Workers AI | AI 面板 | 每日 Neuron 用量 |

历史教训：2026-09-08 D1 读额度 3 天烧 47%，根因是后台访客分析 30s 自动刷新 × 全表扫描（docs/访客治理方案.md），现已治理。

## 五、备份

- **命令**：`npx wrangler@<固定版本> d1 export whizzzest --remote --output=d1-backup-YYYYMMDD.sql`；
- **频率**：每月一次 + 每次改库前；
- ⚠️ **导出文件含访客 IP / UA 等个人信息：不进 git、不走聊天工具**，只存本地受控位置；
- R2 桶无需备份（内容由 D1 引用，删内容时代码已做级联清理）。

## 六、排障固定顺序（八步）

1. **分类**：静态页 / 动态页 / 后台 / 商户·作者门户——四类对应四个 Worker，先锁嫌疑人；
2. **全挂还是部分挂**：全挂 → 查 Actions 部署记录与平台状态页；只有特定功能坏 → 查对应模块最近提交 diff；
3. **本地复现**：本地起完整环境（本地 D1）把线上问题变成本地可调试问题；
4. **看日志**：observability 按报错时间 + 请求路径对照代码；
5. **查数据**：内容不显示 / 状态不对先查 D1 对应表（审核状态、上下线状态最常见）；
6. **两层缓存**：浏览器缓存有指纹机制一般没事；**PWA 离线缓存**会让部分访客停在旧版——先确认 sw.js 版本戳变没变，让用户强刷或等缓存自动更新；
7. **恢复优先于修复**：先回滚恢复服务再定位根因，不要在线上边修边等；
8. **留档闭环**：「现象 + 原因 + 解法」写进文档（文字 + 按需附图，不堆二进制截图）。

## 七、已知事项

- CI 的 Post-deploy smoke（scripts/smoke.sh）在 GitHub runner 上曾出现出站访问全部超时（2026-09-08，同 run 内 Cloudflare API 正常、本机探测全绿），疑为边缘安全设置质询数据中心 IP——该 job 设计为不拦截部署；后续可在 Cloudflare 安全规则按 UA 尾缀 `whizzzest-smoke` 放行；
- 主站 Worker 无会话密钥类 secret（只有 SMTP 通知相关），本地出站 SMTP/AI 在 workerd 内会挂起，本地调试这两类功能依赖 mock 或线上验证。
