## 三、扩展性诊断（事实与证据）

### 3.1 新增一个板块 = 8+ 个散落登记点（最大瓶颈）

实测清单：`worker/index.js` import + 正则 alternation（:98）+ 三元链（:103-107）；`wrangler.jsonc` run_worker_first（现 32 条手列路径）；`build.js` sitemap 动态条目 + robots.txt + DYNAMIC_ZH_ROUTES；`worker/ai.js:53-55` PAGE_ROUTE_RE 白名单；`handleStats` 表白名单（worker/index.js:338-344）；admin 导航 anav（admin/index.js:2449-2457）；`worker/strings.js` zh/en 双字典；schema + migrations。漏改无任何编译期/测试期报错。→ **B2 对症**。

### 3.2 主站五模块「页面骨架五连拷」，已实际漂移

`getChrome/pageShell/esc/notFound/htmlResponse` 在 tv/library/music/attractions/merchants 五模块各一份（约 350-400 行），靠「对标 tv.js」注释维系。漂移实锤：theme-color 两个值（#2b1208 ×2 / #fbfbfd ×3）、og:type 四种、worker/index.js:432-434 的 esc 是不转义引号的弱化版。另 sitemap 生成器 ×4、`/api/<x>/latest` + 60s 实例缓存模式 ×4、fmtDate ×3。→ **B1 对症**。

### 3.3 admin 单文件 5082 行，板块「复制即扩展」

56 条 if 路由 + 93 个服务端函数 + LOGIN_HTML/APP_HTML 两个巨型模板 + **2185 行内联客户端 JS**。loadTv/loadMusic/loadAttra 逐行同构（仅变量前缀不同）；历史 commit 实证每加板块 +460~735 行、改动面 6 处；showView 9 连硬编码 classList.toggle（admin/index.js:2973-2981）。已有真实事故（内联模板字符串劈断 // 注释致后台全卡）。docs/加功能检查单.md:23 预留的 W9 拆分一直未动。→ **B3 对症**。

### 3.4 游戏收录管线：8 步手工、元数据零校验（A5 已补校验）、上传无增量

收录一款 = 放包 → 清洗 → runtime-repair 自愈 → 手写 games.json → 手写 games.en.json →（in-house 加 JS_SOURCES）→ upload-games.mjs → check-i18n → 部署。games.en.json 已 100% 覆盖（40/40），双写是既定设计（决策③母本+覆盖表）但成本真实。upload-games.mjs 逐文件 spawnSync 起 wrangler 进程、无并发、无清单对账（重跑即全量）。每款游戏的适配知识（垫片/键修正/补抓）只活在包文件与 commit message。→ **B4/B7 对症**（校验部分 A5 已落地）。

### 3.5 i18n 事实源四处分裂

构建期 src/data/*/strings.json（静态页+客户端 JS，window.__I18N/build-meta.json 两路分发）、worker/strings.js（动态板块，zh/en 逐键双镜像 ~300 行 + 手工 .replace 插值链，漏 replace 即原样输出 {n}）、game/strings/（第三套，有 check-i18n 看护）、D1 内容（无双语字段——**业主拍板过的妥协，不算问题**）。加一个 locale 要碰 4+ 处。→ **B6 对症**（只打通主站两套）。

### 3.6 三门户平台层三抄，安全参数三处同步

writer「照抄商户门户」（writer/index.js:5 自述）：加密五件套三份逐字相同、邮箱验证码整块 merchant/writer 两份 60% 相同、图片魔数校验三份、webauthn D1 回调三份。shared/webauthn.js 已是真三端共用、portal-ui.js 覆盖 merchant/writer（admin 只取 2 个片段）——共享机制是通的，覆盖面没铺开。风险：PBKDF2 轮数、限流阈值等安全参数改动需三处同步，漏一处即安全差异。→ **B5 对症**。

### 3.7 次级观察项

- **审核状态词汇不统一**：published|hidden vs pending|approved|rejected（+expired/draft）散布 5+ 张表，PUB_WHERE 每模块各写各的、handleStats 混写两种字面量。未来跨板块搜索/统一审核流前需先统一（可只统一新表 + 映射层，不做存量迁移）。
- **D1 单库多业务共享配额**：访客明细（每日 cron 清理）、播放计数、AI 日志同库挤 rows_written。访客治理方案（W1）已管住大头，观察即可。
- **主站全部静态文档页走 Worker**（run_worker_first 含 /about /cuisine 等 7 个纯文档路径，只为访客采集注入）——有意设计；流量上来后是成本项，届时可评估「采集改 R2 回调/采样」。

## 五、B 档：结构性改进（立项候选，逐项拍板后执行）

### B1 主站 Worker 页面骨架收敛为 shell 模块
- **内容**：新建 `worker/shell.js` 承载 getChrome/pageShell/esc/notFound/htmlResponse（含 siteCard 级 sitemap 生成器与 latest+60s 缓存工厂可选），tv/library/music/attractions/merchants 五模块改 import；以 tv.js 版为基准，diff 各模块差异项（og:type、theme-color、body class）参数化。
- **收益**：消 ~350-400 行重复；顺手消灭已发生的漂移（theme-color/og:type 统一须业主确认预期值）；站点级 head 变更从此单点。
- **与零依赖惯例的关系**：不冲突——worker/ 内部已有 strings.js 互引先例；「零依赖不做共享模块」原指不引 npm 包（library.js:58-59 注释语境）。
- **风险**：低。五页 HTML 输出应与改前逐字节一致（漂移项除外，须业主逐项拍板取哪个值）。
- **验收**：五板块 zh/EN 各页 curl 对比改前快照，仅拍板过的漂移项不同；`node build.js` 产物不变。

### B2 板块登记点收敛（把检查单从散文变代码）
- **内容**：建一份单一注册数据（建议 `worker/sections.json` 或 `shared/sections.js`：route / 表名 / 是否有 sitemap / admin 入口），消费方：build.js DYNAMIC_SECTIONS（A4 已就位，直接对接）、worker/index.js 正则+分发、handleStats 表清单、ai.js PAGE_ROUTE_RE、admin anav 可后接。至少先落**校验脚本**（scripts/check-sections.mjs）：核对 run_worker_first ⊇ 注册路由、sitemap 条目一致、ai.js 白名单一致，接进 CI check job。
- **收益**：新增板块的 8+ 登记点降为「注册表 + 模块文件」；漏改由脚本拦截，与 check-i18n 同哲学。
- **风险**：低-中。worker/index.js 分发重构是主站行为面，需 curl 快照对照。
- **验收**：check-sections 全绿；人为删一处 run_worker_first 能被脚本抓住。

### B3 admin 拆分（= 全站优化方案 W9）
- **内容**：分两步。① APP_HTML 的 2185 行内联 JS 拆为真实 .js 静态文件（admin 加 assets 目录 + wrangler assets 绑定；顺带把 CSP 从 `unsafe-inline` 往 script-src 收敛）；② 六组同构板块代码参数化：客户端一套通用列表-表单-审核渲染器 + 服务端一个通用 CRUD 工厂（配置驱动：表名/字段/校验/文案），9 板块改配置。
- **收益**：admin 5082 行预计缩 1/3+；新板块从「+700 行」变「+配置」；内联脚本事故（f36c4b0）根除。
- **风险**：中-高（后台全功能面）。必须分两步走、每步真浏览器全板块回归（业主过一遍 9 个 Tab）。
- **验收**：步①后 CSP 报告零违规；步②后 9 板块 CRUD/审核/上传全回归；行数对账。

### B4 upload-games.mjs 升级：并发 + 清单对账
- **内容**：并发上传（4-6 路）+ 本地↔R2 清单对账（`wrangler r2 object ls` 建索引，只传缺失/变更；--check 模式只报告）；顺带把 MIME 表收敛为单份（upload-games.mjs 读 game/worker/index.js 导出的表，或抽 game/shared/mime.js 两边引）。
- **收益**：5479 文件全量重传从小时级降到分钟级；百款规模前置。
- **风险**：低。注意 wrangler 并发限速与 `--pipe` 稳定性（看板 09-10 记录：--file 路径 fetch failed、--pipe 稳定，保留 --pipe 路径）。

### B5 三门户平台层下沉 shared/
- **内容**：加密五件套（hmacHex/sha256Hex/pbkdf2Hex/toHex/timingSafeEqual）、邮箱验证码整块、readImage 魔数校验、IP 限流、html/json/redirect/esc 响应工具下沉 shared/（仿 webauthn.js 的 createWebAuthn 工厂模式：createCrypto(secretName) 等），三门户改 import。会话/账号表结构保持各门户独立（见 C 档）。

## 六、C 档：评估过、明确不做（留档防重复提议）

| 提议 | 不做的理由 |
|---|---|
| 合并 4+1 个 Worker 为单体 | 隔离是拍板过的设计（「后台挂了不影响主站」，设计架构与方案 §302）；爆炸半径分离是本项目优点；CI 顺序部署已收敛流程 |
| 上静态站框架/打包器（eleventy/astro/esbuild）替代 build.js | 15 个静态页体量下自建零依赖构建已在工作且是全组会话熟悉资产；替换属负收益重构。A4 已把 build.js 里可数据化的部分数据化，维持即可 |
| 统一三套账号体系（admin/merchant/writer） | 刻意隔离（schema.sql:257-259 不同表不同会话密钥，同手机号两边各注册是既定行为）；除非未来出现跨门户登录诉求，否则不动 |
| D1 内容双语字段 | 业主拍板「不做」：EN 界面 + 内容回退中文是既定行为（worker/strings.js:4-9） |
| 主站 strings / 游戏站 strings / worker strings 三站大统一 | 收益低风险高；B6 只打通主站两套已覆盖主要痛点 |
| 游戏收录管线自动化编排（一条命令收录） | 收录的瓶颈在「逐款人工验收可玩性」，不在步骤数量；B4+B5(A5) 已把可自动化部分自动化 |
| 审核状态字段全量迁移统一（published/approved 二选一） | 存量迁移风险大于收益；新表按新词汇、跨板块查询走映射层即可 |
